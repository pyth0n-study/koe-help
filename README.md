# 声ヘルプ

飲食店の洗い場とホールの状況共有を支援する、音声操作対応のWebアプリです。

洗い場担当者が「手伝いに来て」と直接頼む心理的負担を減らすため、救援要請だけでなく、現在の忙しさを青・黄・赤の3段階で共有します。ホール側は大きな色表示から状況を把握し、「確認しました」「今から向かいます」の2段階で応答できます。

## 解決したい課題

飲食店の繁忙時、洗い場は1人で担当することがあり、食器が集中するとホールの応援なしでは対応が難しくなります。一方で、次の問題があります。

- 洗い場とホールに距離があり、蓄積状況が見えない
- ホールにも接客などの業務があり、毎回確認へ行くことが難しい
- 洗い場から「手伝って」と直接頼むことには心理的負担がある
- 応援を求めても、相手に伝わったか分からずストレスになる

そこで、依頼ではなく状況共有を中心に設計しました。

## 主な機能

### 洗い場モード

- 「ステータス青・黄色・赤」の音声操作
- 「ホールヘルプ」による緊急要請
- 現在状態と経過時間の大きな表示
- ホールの確認・対応状況の表示
- 音声が使えない場合の手動操作

### ホールモード

- 洗い場の状態を青・黄・赤で即時確認
- 「確認しました」と「今から向かいます」の2段階応答
- 古いステータスへの警告
- タブタイトル、振動、ブラウザ通知による変化の通知

### 履歴・設定

- 状態変更、確認、対応、完了の履歴
- 直近24時間の発生回数と平均反応時間
- 黄色・赤の更新警告時間の設定
- 端末ごとの振動設定

### 通信

- 複数端末間の約2秒ごとの同期
- オフライン状態の明示
- オフライン中の操作を一時保存し、回復後に自動再送
- 再送時の二重登録防止

## 設計変更の経緯

当初は「ホールヘルプ」と発話して応援を直接要請する設計でした。しかし、自分で試した結果、忙しくても直接助けを求めること自体に遠慮があり、機能が存在しても使われない可能性に気づきました。

そこで、中心機能を「助けを求める」から「現在の状況を共有する」へ変更しました。ホール側にも即時対応を強制せず、まず状況に気づいたことだけを返せるようにしています。

カメラや重量センサーによる自動判定も検討しましたが、導入費用、店舗への依頼、プライバシーを考慮し、今回の開発範囲からは除外しました。

## 音声認識で得た知見

実機テストでは、次の表記揺れが発生しました。

- 洗い場 → アライバル
- ホール → コール、オール
- 赤 → アカ
- 黄色 → キイロ

認識結果を正規化し、意味を判定する処理を画面から分離しています。句読点は除去しますが、「ステータス」「ホール」に必要な長音記号は維持します。

18件の自動テストにより、表記揺れへの対応と通常会話への誤反応防止を確認しています。

```powershell
npm run test:voice
```

## データとプライバシー

保存する情報は、状態、操作種別、時刻、反応時間です。音声データ、発話内容、従業員の個人名は保存しません。

## ローカルでの起動

### 必要環境

- Node.js 22.13.0以上

### 起動方法

```powershell
npm install
npm run dev
```

表示された `http://localhost:3000` をブラウザで開きます。

### 品質確認

```powershell
npm run lint
npm run test:voice
npm run build
```

## 動作確認の流れ

1. ブラウザで2つのタブを開く
2. 一方を洗い場モード、もう一方をホールモードにする
3. 洗い場側で「ステータス赤」と発話する
4. ホール側へ状態が反映されることを確認する
5. ホール側で「確認しました」「今から向かいます」を操作する
6. 洗い場側へ応答状況が反映されることを確認する
7. 履歴画面で一連の操作を確認する

## 現在の制約

- 音声認識精度は端末、ブラウザ、騒音環境に依存する
- ブラウザ通知はHTTPS環境や端末側の許可が必要
- 状態は現在1店舗・1洗い場を前提としている
- 画像・センサーによる混雑度の自動判定は対象外
